**WS-1. Coordinate publication of every current and future workspace package at one shared version with path-qualified tags.**
*Because* A durable all-packages rule remains unchanged as releases and workspace members are added.
*Accepting* An exceptional package requires a separate decision or an amendment to this rule.
*Rejected* Naming current members, which would change the entry when membership grows; fixing the entry to one release, which would change it every release; and a coordinating root tag, because coordination does not publish the root.

**WS-2.** *Superseded by* WS-4

**WS-4. Publish each package release as a complete annotated-tag record and a host projection, using supervised, ordered and retry-safe ordinary commands, and mark the stable coordinated language release as the host's verified Latest projection after every package verifies.**
*Because* A semantic paragraph in the path-qualified tag is the complete portable release record, while the host release projects it without owning substantive content; exact approval and state checks safeguard publication without custom machinery. The language release is the workspace's public Latest entry point, so package dependency order and host automatic selection must not leave another package in that position.
*Accepting* Source changes are merged before the full release commit and package scope are selected from the issue and workspace decisions. Each tag message is one plain-text paragraph of semantic package changes, with no title duplication, commit list, Markdown structure, links, cross-references or coordination metadata; the host release takes it directly from the local annotated tag under a package-version title, after complete command preflight and read-only resolution confirm the selected repository without a create-time repository override. The person explicitly approves the exact commit, tags and paragraphs before any push. Dependencies publish before dependents where applicable. Existing local and remote tags and host releases are inspected before creation; exact existing pieces may be skipped, while any mismatch stops for the person, and existing state is never moved, edited, deleted, overwritten or automatically repaired except for the separately approved metadata-only action marking the new stable language release Latest. That action follows verification of every package, is skipped when its exact state already stands, and is verified through both the visible release marker and the host's canonical Latest endpoint before the release issue closes. A prerelease has no Latest write because the host excludes prereleases from that state; verification instead preserves the stable release-list marker and canonical endpoint recorded before publication. The milestone closes only when no open issues remain.
*Rejected* Host-only substantive content, separate notes files, release TOML, custom plans, checkers or derived files, an independent release-reviewer role, a source pull request for a release without source changes, forced tag updates, combining local tag-note projection with a create-time repository override, relying on publication order or automatic host selection for Latest, and the former prohibition of every custom Latest policy, which allowed another package to become the workspace's public entry point.

**WS-3. Give the language definition, core library and toolchain one Quoll workspace namespace, with the package leaves `language`, `std` and `toolchain`.**
*Formerly* QUOLL-8
*Because* the parallel leaves distinguish the definition, core libraries and tools without relying on repository layout, while the shared namespace groups them and remains open to future packages.
*Because* `language` identifies this package's contents without the redundant `quoll/quoll` leaf; Quoll remains the programming language's name, while `language` is this package's canonical leaf and default local name.
*Accepting* that this package's former default local name changes to `language`, and that the core library and toolchain use `std` and `toolchain` beneath the same namespace when their [language.layout.manifest]s are written.
*Rejected* keeping `quoll` as this package's leaf, which repeats ecosystem and workspace without saying that the package is the definition; and flattened leaves repeating the workspace in every package name, which moves grouping into each name and makes future renaming more likely.
