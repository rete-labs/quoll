**WS-1. Coordinate publication of every current and future workspace package at one shared version with path-qualified tags.**
*Because* A durable all-packages rule remains unchanged as releases and workspace members are added.
*Accepting* An exceptional package requires a separate decision or an amendment to this rule.
*Rejected* Naming current members, which would change the entry when membership grows; fixing the entry to one release, which would change it every release; and a coordinating root tag, because coordination does not publish the root.

**WS-2. Publish each package release as a complete annotated-tag record and a host projection, using supervised, ordered and retry-safe ordinary commands.**
*Because* A semantic paragraph in the path-qualified tag is the complete portable release record, while the host release projects it without owning substantive content; exact approval and state checks safeguard publication without custom machinery.
*Accepting* Source changes are merged before the full release commit and package scope are selected from the issue and workspace decisions. Each tag message is one plain-text paragraph of semantic package changes, with no title duplication, commit list, Markdown structure, links, cross-references or coordination metadata; the host release takes it directly from the tag under a package-version title. The person explicitly approves the exact commit, tags and paragraphs before any push. Dependencies publish before dependents where applicable. Existing local and remote tags and host releases are inspected before creation; exact existing pieces may be skipped, while any mismatch stops for the person, and existing state is never moved, edited, deleted, overwritten or automatically repaired. Ordinary Git and host reads verify the published tag and projection before the release issue closes; the milestone closes only when no open issues remain.
*Rejected* Host-only substantive content, separate notes files, release TOML, custom plans, checkers or derived files, an independent release-reviewer role, a source pull request for a release without source changes, forced tag updates, and a custom Latest policy.
